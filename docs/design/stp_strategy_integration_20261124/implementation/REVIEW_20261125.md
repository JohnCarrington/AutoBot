## 1. BROKEN opportunities and the destination: DEFECT, corrected

**Code.** `OpportunityKeeper.five_minute` ran the single tracker's 5-minute checks only for WAITING and ACTIVE, so no
destination check ran while BROKEN. The re-plan's D-1 check (`assess` → `zones.reached`) looks at the latest finished
5-minute candle only, and `m5_checked_until` moves on at every run, so the skipped candles were never seen again.

**Demonstrated on d6056ba** (R1: SELL 13240-13250, primary 13170, destination zone 13165-13170):
- 09:05 Watch & Wait; the 09:00 hourly closes 13253 (3 pips beyond 13250): BROKEN at 10:00;
- 10:30 a 5-minute candle reaches 13168 (the destination); the 10:00 hourly closes back inside at 13245;
- result: at 11:00 the opportunity is back in **Watch & Wait** (`failed breakout`), no `completed` event, and
  `authorise` **allowed** a sell confirmed at the zone at 10:55, key `STP-GBPUSD-20261117-0900-1#t1`.

**Correction.** While BROKEN, the single tracker's own 5-minute check still runs on each candle with the record
treated as live, so only its destination rule can act (its zone activation needs WAITING): a destination reached while
BROKEN ends it, COMPLETED (after the zone) or INVALIDATED (before it), with the same evidence and ambiguity rules.
After: R1 ends it COMPLETED at 10:30 and the same sell is refused.

## 2. The duplicate key after a zone change: DEFECT, corrected

**Code.** `which_test()` recounted the D-25 tests over every hourly candle since the lineage began, against the
opportunity's current zone. The design (section 10) says n "is a function of the rejection candle alone, so ... a
later re-plan ... cannot change it", and section 6.1 that a successor "keeps its history and test count".

**Demonstrated on d6056ba.**
- R2a: the same rejection candle (07:40) is test **1** against 13240-13250 and test **2** after the zone is widened
  to 13235-13250 (an earlier hour that missed the old zone by 3.5 pips is inside the new one). A traded test keyed
  `#t1` would be keyed `#t2` after the change, so rule 11 would let a second trade in the same test through.
- R2c: after a supersession to a zone that does not overlap, a genuine new test at the new zone is numbered **1**
  again, the key of the test already traded at the old zone, so it would be refused as a duplicate.

**Correction.** The tracker records the lineage's tests (`tests`: each finished hourly candle counted once, by the
same D-25 rule, against the zone in force at that hour; inherited on supersession). `which_test()` takes the hours
the tracker has counted from that record and counts only later hours against the current zone. A file without the
record (written before it) is counted as before. After: R2b keeps `#t1` across the zone change; R2c gives test 2.

## 3. Structural freshness: DEFECT, corrected

**Code.** The tracker marks each run `current` (fresh 5-minute and hourly candles, and re-planned at the latest
finished hourly candle) with `not_current_reasons`; `authorise()` checked only `written_utc` and the price age. The
design (section 4): "If current.json ... is not current (§9.2) ... gated ideas are refused."

**Demonstrated on d6056ba.** R3: a file written a minute earlier, `current: false`, `data_fresh: false`, reason "the
hourly candles are out of date" (e.g. the hourly candles stopped while 5-minute candles still arrive): **authorised**.

**Correction.** `authorise()` refuses unless the tracker marked its run current, giving the tracker's own reasons.
Two hand-built test states (T-28 to T-66 `auth_state`, FT-R1 `_race_states`) now carry `current: true`, as a current
tracker run writes them.
